# Admin API

The Admin API provides tenant lifecycle management. It is exposed on the
**External Task API** surface (port 8084) under the `/admin/*` path prefix.

## Authentication

The Admin API does **not** accept OAuth2 client_credentials JWTs. It requires
a **Kubernetes ServiceAccount bearer token** whose SA carries the
`agentorc.io/admin: "true"` label.

```bash
# Obtain an admin SA token
kubectl create token agentorc-admin -n agent-orc-system

# Use it with aoctl
aoctl admin tenants list --token $(kubectl create token agentorc-admin -n agent-orc-system)
```

The operator validates the SA token via the Kubernetes TokenReview API and
checks the `agentorc.io/admin` label on the ServiceAccount. Unlabeled SAs
receive `403 Forbidden`.

## Endpoints

| Method | Path | Description |
|---|---|---|
| `GET` | `/admin/tenants` | List all tenants |
| `POST` | `/admin/tenants` | Create a new tenant |
| `GET` | `/admin/tenants/{name}` | Get a tenant by name |
| `DELETE` | `/admin/tenants/{name}` | Delete a tenant |
| `POST` | `/admin/tenants/{name}/rotate-secret` | Rotate a tenant's client secret |

### GET /admin/tenants

List all tenants.

**Response:**

```json
{
  "tenants": [
    {
      "name": "acme",
      "namespace": "agentorc-system",
      "clientID": "acme-client",
      "targetNamespace": "tenant-acme",
      "allowedAgents": ["support-bot"],
      "rateLimit": {"requestsPerMinute": 60, "concurrentRuns": 10},
      "budgetPerDayUSD": "100.00"
    }
  ]
}
```

### POST /admin/tenants

Create a new tenant. This writes a `TenantConfig` CRD and a client-secret
`Secret` in the `agentorc-system` namespace.

**Request body:**

| Field | Type | Required | Description |
|---|---|---|---|
| `name` | string | yes | Tenant name (used for the `TenantConfig` name) |
| `targetNamespace` | string | yes | Namespace where the tenant's agents run |
| `clientID` | string | yes | OAuth2 client ID |
| `clientSecret` | string | no | Initial client secret (auto-generated if omitted) |
| `allowedAgents` | []string | no | Agent names this tenant can access |
| `rateLimit.requestsPerMinute` | int | no | Max task submissions per minute (0 = unlimited) |
| `rateLimit.concurrentRuns` | int | no | Max concurrent runs (0 = unlimited) |
| `budgetPerDayUSD` | string | no | Daily spend ceiling in USD |

**Response (201):**

```json
{
  "name": "acme",
  "namespace": "agentorc-system",
  "clientID": "acme-client",
  "clientSecret": "auto-generated-secret-abc123",
  "targetNamespace": "tenant-acme",
  "allowedAgents": ["support-bot"],
  "rateLimit": {"requestsPerMinute": 60, "concurrentRuns": 10},
  "budgetPerDayUSD": "100.00"
}
```

> **Note:** `clientSecret` is included **only** in the create response. It is
> never retrievable afterwards. Save it immediately.

### GET /admin/tenants/{name}

Get a single tenant by name. Returns the same shape as a tenant entry in the
list response (without `clientSecret`).

### POST /admin/tenants/{name}/rotate-secret

Rotate the client secret for a tenant. The new secret is generated by the
operator and returned in the response.

**Response (200):**

```json
{
  "name": "acme",
  "clientID": "acme-client",
  "clientSecret": "new-secret-xyz789"
}
```

### DELETE /admin/tenants/{name}

Delete a tenant. This removes the `TenantConfig` and associated client-secret
`Secret`. Existing `AgentRun` resources in the tenant's namespace are not
automatically cleaned up.

**Response:** `204 No Content`

## Using the CLI

All admin operations are available via `aoctl admin tenants`:

```bash
# List
aoctl admin tenants list --token $SA_TOKEN

# Get
aoctl admin tenants get acme --token $SA_TOKEN

# Create
aoctl admin tenants create acme \
  --namespace tenant-acme \
  --client-id acme-client \
  --allowed-agents support-bot,faq-bot \
  --rpm 60 \
  --concurrent 10 \
  --budget 100.00 \
  --token $SA_TOKEN

# Rotate secret
aoctl admin tenants rotate-secret acme --token $SA_TOKEN

# Delete
aoctl admin tenants delete acme --token $SA_TOKEN
```

## Using Terraform

For infrastructure-as-code, you can provision tenants using the
[Terraform example](../examples/terraform/agentorc_tenant.tf) instead of the
admin API. Both approaches produce identical Kubernetes resources.

```bash
terraform init
terraform apply -var="tenant_name=acme" -var="client_id=acme-client"
```

## Rate limiting & budget

When creating a tenant, set `rateLimit` and `budgetPerDayUSD` to control
resource usage. See [Rate Limiting & Budget Enforcement](rate-limiting.md)
for details on how these are enforced and what HTTP responses clients receive
when limits are exceeded.
